01

Understand dual-write storage

The SDK writes locally first and then mirrors transcript batches through append. A store is a mirror, not a replacement for local execution files.

02

Use the SDK memory store

Run two actual queries with one InMemorySessionStore instance. The second loads the first conversation. The memory store disappears when that process exits.

03

Build an ordered file adapter

Implement append and load, preserve opaque entry payloads and ordering, deduplicate UUID retries, and validate the adapter with Anthropic’s official 13-contract suite.

04

Resume after a worker exits

Run a new process with the same working directory, a clean SDK configuration and the shared adapter. The restart test removes the source local config before resuming.

05

Inspect and manage stored sessions

Use native listSessions, getSessionMessages and deleteSession helpers with the adapter. Optional summaries speed listing; subkeys preserve transcript namespaces.

06

Observe failure and option boundaries

Inspect actual mirror_error events, missing-store fallback and startup conflicts. persistSession false and file checkpointing cannot be combined with a store. This lab simulates hosts locally.
