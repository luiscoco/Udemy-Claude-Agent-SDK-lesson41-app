01

Real boundary of this demo

Two worker processes with isolated SDK config directories simulate host changes on one computer, using the same cwd. The backing adapter is a local file store outside those configs. No remote containers or cloud services are claimed.

02

Local-first and temporary copies

Fresh queries leave a local JSONL until this lab cleans up. Store-backed resumes materialize history into SDK-managed temporary configuration and clean that materialized copy at run end. External mirroring does not mirror general project files.

03

Ordering and retry rules

Persist entries as opaque JSON values, in order. Stable UUIDs are deduplicated to make retries idempotent; metadata without UUIDs stays append-only. This adapter serializes one instance, not concurrent processes.

04

Production adapters

S3 reference adapters store ordered JSONL parts. Redis uses lists and a session index. Postgres stores ordered JSONB rows. Copy and adapt official examples; use transactions/CAS for multiple writers, secure credentials, encryption and retention controls.

05

Optional methods

listSessions enables continue. listSessionSummaries uses incremental SDK folds to avoid loading every transcript for metadata. delete cascades from the main key to subkeys. listSubkeys discovers subagent namespaces; this lab does not invoke subagents.

06

Failure is observable

An injected append outage produces actual native mirror_error messages. The model can still finish using local history. A missing store can fall back to local storage; the missing experiment deliberately has a clean target configuration, then starts a healthy fresh session.

07

Validation and lifetime

The file adapter passes Anthropic’s official 13-contract suite adapted only to Node’s test runner. Additional tests cover UUID retries and overlapping calls. In-memory state dies with the process; the file store is durable across workers but deliberately removed after each classroom experiment.
